# Markdown Style Guide

## Headings
- Use H1 once per file.
- Use H2 for major sections.
- Avoid deep nesting unless needed.

## Tables
- Keep consistent column order for specs.
- Prefer numeric ranges over single-point estimates.

## Lists
- Use ordered lists for workflows.
- Use unordered lists for feature summaries.

## Links
- Use relative links for all internal references.
- Verify links after adding new files.

## Naming
- File names should be lowercase and use underscores.
- Keep names descriptive and short.
